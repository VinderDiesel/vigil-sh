# 路线图与决策门

日期是承诺不是愿望。每个门未通过 → **收缩范围或转向**，绝不通过增加功能来掩盖证据不足。

## G1 — 第 14 天：采集与最小化可行

| 项 | 内容 |
|---|---|
| 交付 | ✅ 三个采集器（`file` / `otel` / `langfuse`）；PII/secret 最小化测试（conformance 覆盖）；lineage（`raw_hash` / `canonical_hash` / `redactions`） |
| 门槛 | 100% 危险字段在测试中不以明文落入产物；≥1 名外部审查者可复现采集 |
| 待验证 | 外部审查者复现（**尚未完成**：需要 1 名外部使用者跑通自己的 trace） |
| 未通过 | 停止建 UI 与签名库，转向 collector-only |

## G2 — 第 30 天：Case → Gate 端到端闭环

| 项 | 内容 |
|---|---|
| 交付 | ✅ `CaseManifest`、脱敏用例、`docker` 环境 + `vigil.harness`、确定性 scorer、JUnit/JSON/PR 评论 |
| 门槛 | 同一快照连续 10 次通过；故意注入的回归 ≥1/1 被拦截；任何破坏性工具不会在真实模式自动执行 |
| 待验证 | 10 次重复运行（需容器环境可用）；破坏性工具真实执行拦截的**外部**验证 |
| 未通过 | 砍掉 MCP proxy，仅保留 `record-only` |

## G3 — 第 60 天：外部适配与协议冻结

| 项 | 内容 |
|---|---|
| 交付 | 3 个外部团队接入；3 个 framework/provider 组合；adapter matrix；conformance 测试 |
| 门槛 | 3/3 团队完成导入；≥2/3 团队复现过一次失败；manifest diff 可解析 |
| 未通过 | 协议收敛到 v1alpha1，暂停跨框架自动发现 |

## G4 — 第 90 天：资产价值与统计有效性

| 项 | 内容 |
|---|---|
| 交付 | 10 个生产（或近似生产）失败转为回归；judge 校准集；flake 分类；重复运行机制 |
| 门槛 | 生产选择集相比等量随机样本，至少在一个采用者处多发现 1 个真实回归；false gate 可解释 |
| 未通过 | 停止"可靠性平台"叙事，转向评测数据治理或治理适配器 |

## 之后（仅在 G1–G4 通过后）

| 版本 | 内容 |
|---|---|
| v0.2 | docker 环境、LLM judge + `audit-judge`（meta-eval）、统计门禁（需声明 MDE）、flake 分类器 |
| v1.0 | SLO 看板、回归 diff、plugin registry、完整 conformance suite |
| v1.5+ | 内部错误签名库（先内部后跨组织）、行业可靠性报告 |

## 追踪指标（不看 star）

1. **下游 CI 采用数**：独立仓库在 CI 中跑 `vigil run` 的数量。
2. **插件 owner 数**（比插件数重要）。
3. **生产失败转化率**：线上失败 → 可重跑回归的比例。
4. **被引用次数**：论文、厂商文档、RFP/选型指南。
5. **可解释性**：阻断决策能否一句话说清。
